### 5. 核心机制解释
1. **进程树建立**：`load_processes` 通过解析 trace 中的 `clone` 返回值建立父子关系，`execution_graph` 将 `cc` 派生的 `cc1` 和 `as` 归入同一个构建作业（同一个 job_id）。
2. **实际依赖图**：`execution_graph` 只记录成功的 `openat`（`ret >= 0`），且只保留项目根目录内的路径；相对路径按 `fork` 时的 `cwd` 折算，项目根外的文件被过滤。
3. **声明依赖图**：`declaration_graph` 从 `# Files` 段提取声明，识别 `.PHONY` 并展开，分离 `|` 后的 order-only 依赖。在我的测试中，验证了 `clean` 被剔除，`build_dir` 被单独存放。
4. **集合差分析**：`analyze` 函数对每个目标，计算实际依赖与声明依赖的差集，得到 MISSING 和 REDUNDANT，并附上具体的 trace 行号/PID 或 make-db 行号作为证据。
