  - 进程归属（processes.json）：make(12)；作业 13 = cc(13)+cc1(14)+as(15)；作业 16 = cc(16)+collect2(17)+ld(18)。
  - 两图：实际图 main.o←{main.c, config.h}、app←{main.o}；声明图 main.o←{main.c, unused.h}、app←{main.o}；

- 核心机制（结合本次运行解释 fullcheck.py）：
  1. load_processes（92–121 行）用 clone 返回值（父进程 trace 中 = 子 PID）建父子表、execve 记录变身；
     要求全树恰一个 make 进程。
  2. execution_graph（124–234 行）job_for 沿父链找"父进程为 make"的祖先作作业根 → cc1/as 归属 cc 的作业 13；
     过滤规则：失败调用（ret<0）不算、相对路径按 fork 时 cwd 折算、项目根外路径丢弃（系统头文件不进图）、
     写打开记产物、O_RDONLY 记依赖、每作业恰一个最终输出否则显式 Unsupported。
  3. declaration_graph（237–301 行）只解析 make -p 数据库 # Files 段；.PHONY 目标剔除并递归展开；
     "|" 后 order-only 依赖单独存放、不参与判定。
  4. analyze（304–329 行）对实际图每目标做集合差：实际−声明=MISSING（证据=trace 文件/行/PID），
     声明−实际=REDUNDANT（证据=make-db 行号+声明原文）。
