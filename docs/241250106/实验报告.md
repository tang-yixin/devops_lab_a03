**核心机制解释（对照本人这次运行）**：
1. `load_processes`（`fullcheck.py:92–121`）按文件名 `t.<PID>` 建进程表，再用每条 trace 中
   `clone/clone3/fork/vfork` 的**返回值**作子 PID 登记父子关系（第 106–111 行，`parent[ret]=pid`）——
   本人 `t.12:55` 的 `clone(...) = 13` 就说明 13 是 make 的子进程；`execve` 成功才记 executable（112–113），
   据此要求全树恰有一个 make（117–120）。`execution_graph` 的 `job_for`（131–142）从某 PID 沿 parent 上溯，
   遇到"父是 make"的那个祖先即作业根：cc1(14)、as(15) 的父是 cc(13)、13 的父是 make(12)，故三者同属作业 13；
   collect2(17)、ld(18) 同理归作业 16。这就是 `processes.json` 里 `job_pid` 一列的来源，也解释了
   "把 cc 派生的 cc1/as 归到同一编译作业"。
2. `visit`（144–208）按 fork 顺序递归，子进程继承的是**父进程 fork 那一刻**的 cwd（163 行 `visit(ret, cwd)`），
   父进程之后的 `chdir` 不影响已 fork 的兄弟；相对路径再由 `project_path`（60–65）折算成绝对路径并判是否在根内。
   本人 `openat(AT_FDCWD, "config.h", …)` 折算为 `/evidence/project/config.h` 保留，而 `/lib/x86_64-linux-gnu/libisl.so.23`
   （`t.14:4`）、`/etc/ld.so.cache`（`t.14:3`）、`/tmp/cc3xJluZ.s`（`t.13:113` 的 unlink）都在根外被丢弃，
   系统头文件/库不会污染依赖图。`ret < 0` 一律跳过（154–155）：`t.12:44` 的 `newfstatat("main.o") = -1 ENOENT`
   与失败的 `clone3` 因此既不产生依赖也不产生假子进程。写打开（`O_WRONLY|O_RDWR|O_CREAT|O_TRUNC`，177 行）
   记入 `job["writes"]`，`O_RDONLY` 记入 `job["reads"]`（182–186）：as 于 `t.15:23` 写出 main.o 成为作业 13 的唯一产物，
   ld 于 `t.18:82` 读 main.o 成为 app 的依赖；每个作业若出现多个最终产物即显式 `Unsupported`（220–221），
   这就是本题"一个 recipe 作业一个产物"的建模前提。
3. `declaration_graph`（237–301）只读 `make -p` 的 `# Files` 段（240–246），跳过 `# Not a target:` 条目、
   以 `#`/`\t`/空格开头的规则体与其它行（247–250），再用 `shlex.split` 拆目标和依赖（260）；
   `.PHONY` 行先收集伪目标集合（263–264），`|` 之后的 order-only 依赖另存 `order_only`、不参与判定（268–269）。
   随后把目标名与依赖名都过 `project_path(name, root, root)`（271–277）得到原始声明表，再用 `expand`（285–293）
   把伪目标递归展开成它真正依赖的文件，返回时剔除伪目标本身（301）。本人数据里 `make-db.txt:1201` 的
   `.PHONY: all clean test` 让 all/test 从声明图消失，只剩 app、main.o 两个真实目标、3 条边。
4. `analyze`（304–329）先分别算出实际图与声明图，再对每个**实际出现过的目标**做两个集合差：
   `observed − specified` → MISSING（312–314，证据 = [读打开证据, 该作业产物写入证据]）；
   `specified − observed` → REDUNDANT（315–318，证据 = make-db 行号 + 声明原文）。本人运行据此得到
   MISSING(main.o, config.h) 的两条证据 `t.14:579`（PID 14 读）与 `t.15:23`（PID 15 写），
   REDUNDANT(main.o, unused.h) 的证据 `make-db.txt:1053` + `main.o: main.c unused.h`。
   注意差集只在"实际构建到的目标"上做，所以声明了但整体没构建的目标不会被判 REDUNDANT，
   这正是 `scope` 字段写 "Single Make process; one final output per recipe job" 的边界所在。
