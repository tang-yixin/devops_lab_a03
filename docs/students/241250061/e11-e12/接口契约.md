# e11e12-1 接口契约（241250061 实测记录）

|接口|请求/响应|状态码|实测证据|
|---|---|---|---|
|POST /v1/jobs|idempotency_key（非空、≤128 字符）、input(mode/repo/base/target/candidate 等)；返回 job_id/status/trace_id|202；错误输入 400；幂等冲突 409|202→QUEUED→RUNNING→SUCCEEDED（job-0efc6de49bef459f9f18bfc8b1d415fc）；重放返回同一 job_id；缺 repo→400 "repo/base/target required"；同键改 target→409 IDEMPOTENCY_CONFLICT|
|GET /v1/jobs/{job_id}|任务状态、trace_id、error|200；不存在 404|轮询终态 QUEUED/RUNNING/SUCCEEDED；崩溃后 FAILED+SERVER_RESTARTED|
|GET /v1/jobs/{job_id}/artifacts|阶段清单与 artifact URI/SHA256|200；结果未生成 409|work/api-client/result.json（RESULT_NOT_READY 于任务完成前）|
|GET /v1/jobs/{job_id}/files/{相对路径}|产物文件与 X-Content-SHA256|200；不存在或越界 404|candidate.patch 下载哈希与清单一致（88074f66c291dcad…）|

任务状态 QUEUED、RUNNING、SUCCEEDED、FAILED、TIMED_OUT；实测补充：服务重启时未完成任务在 Store 初始化时标 FAILED/error.code=SERVER_RESTARTED（"Resubmit with a new key"），已完成任务仍可查询（work/api-jobs/job-870c3f4691e54a69993085236456e92e）。

输出 envelope 的 schema_version、job_id、trace_id、kind、commit、status、data、artifacts 为消费者依据；artifact://job编号/相对路径 由该任务文件接口解析；MD 消费需核对目标 commit 与内容哈希（check_envelope+load_artifact）；基线与目标提交不同是正常的，必须记录两者。

真实项目适配时将仓库和候选准备到 API 服务器 data/ 下（repo/candidate/fixed_report 须经 /course/data 路径校验）；服务仅开放到本地，A/B 通过 SSH 转发访问。
