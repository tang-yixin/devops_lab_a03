# e11e12-1 接口契约（241250093 实测记录）

端口 8081（`python3 run_e11e12.py serve --port 8081`，仅绑定宿主 127.0.0.1）；幂等键一律带学号。
证据：`work/api-client/联调记录.json`、`work/api-client/重启契约.json`、`work/api-jobs/`。

|接口|请求/响应|状态码|本人实测证据|
|---|---|---|---|

|POST /v1/jobs|`idempotency_key`（非空字符串、≤128 字符）、`input{mode,repo,base,target,candidate,fixed_report,expected_output,build_timeout}`；返回 `job_id`/`status`/`request_hash`|202；错误输入 400；幂等冲突 409|`e12-241250093-first` → 202 → `job-d96cd9155f0346d2a4238e4164b45a95` QUEUED → RUNNING → SUCCEEDED；同键同输入重放 202 且同 job_id（job 目录数 1→1）；同键改 target → `409 {"error":"IDEMPOTENCY_CONFLICT"}`；缺 repo → `400 {"error":"repo/base/target required"}`；空串/非字符串键由 `StudentContract241250093` 在 Store 层验证拒收|

任务状态：QUEUED、RUNNING、SUCCEEDED、FAILED、TIMED_OUT。实测补充：服务重启时，Store 初始化扫描
`work/api-jobs/job-*/state.json`，把 QUEUED/RUNNING 标为 FAILED 且 `error.code=SERVER_RESTARTED`
（"Resubmit with a new key"）；SUCCEEDED 任务及其产物不受影响。本人演示在 0.02 秒轮询到 RUNNING 的第 1 次迭代
即 `docker kill 0427da9a6e82`，避免缓存热后任务 6–8 秒就完成导致杀不到。

输出 envelope 的 `schema_version`、`job_id`、`trace_id`、`kind`、`commit`、`status`、`data`、`artifacts`
为下游消费依据；`artifact://job编号/相对路径` 由文件接口解析；MD 消费需核对目标 commit 与内容哈希
（`check_envelope` + `load_artifact`），本人 STALE_REPORT 演示见 `work/e11-b-stale-01/result.json`。
基线与目标提交不同是正常的，必须分别记录：固定样例 `9317562… → 0a0fa4a…`，
真实项目 `e3a1eda… → f443489…`。

真实项目适配时把仓库与候选放在 API 服务器 `data/` 下（repo/candidate/fixed_report 必须落在
`/course/data` 内，否则 400）；服务仅开放到本地，A/B 通过 SSH 转发访问。
